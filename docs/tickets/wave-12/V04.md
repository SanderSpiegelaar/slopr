## Goal

Lay the ground every v1 rule ticket builds on, so those tickets touch only their own module.

## Scope

- `rules/mod.rs`: add `Check::Project` and `Check::Diff` per Rule kinds, a runner for each, and the new modules in `FAMILIES`. Each new module holds `pub const RULES: &[Rule] = &[];`. Module names: `suppression` (family `suppress/`, so it does not clash with `src/suppress.rs`), `naming`, `abstraction`, `config` (family `config/`), `complexity`, `dup`, `pr`.
- `rules/mod.rs`: runners take the `Config` and run a rule on a file when `Config::severity(rule, path)` is `Some`, giving the finding that severity. This replaces the `default_on` check in `file_hits` and the severity filter in `main.rs`, so `slopr.toml` can turn on a rule that is off by default.
- `main.rs`: drop the severity filter. Run Project rules after File rules. Run Diff rules only in diff mode, passing the `Diff` from V01.
- Unit tests in `rules/mod.rs` with test-only rules: `project_check_maps_file_index`, `diff_check_runs_only_in_diff_mode`.
- `tests/rules.rs`: for a rule whose fixture dir holds `bad*` files in subdirs `bad/` and `good/`, run `slopr check .` inside that subdir, so Project rules see several files at once. Markers work as before.

## Out of scope

- Any real v1 rule.

## Acceptance criteria

- Both unit tests pass, and all existing tests still pass.
