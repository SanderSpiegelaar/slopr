## Goal

`slopr check <PATHS>` walks, parses, runs one real rule and prints human output with the right exit code. Every later ticket plugs into this pipeline.

## Scope

- `Cargo.toml`: add every v0 crate in `dependencies.md` at the listed version: clap (derive), serde, serde_json, toml, ignore, globset, rayon, regex, aho-corasick, tree-sitter, tree-sitter-typescript, tree-sitter-python, tree-sitter-rust, semver, anyhow, thiserror, and dev-deps insta and assert_cmd. Not tree-sitter-go. Use the version S00 recorded if one differs. All v0 crates land here, so rule tickets never touch `Cargo.toml`.
- `finding.rs`: `Severity`, `Span`, `Origin`, `Finding`, and `fingerprint()` per the Fingerprint section.
- `source.rs`: `Lang` (no `Go` variant yet), `Parsed`, `SourceFile`, a line index, byte-to-`Span` conversion, `SourceFile::in_test(node)`, and two iterators every comment and string rule uses. `comments()` yields `(Span, text with markers stripped, is_doc)` per comment node. `strings()` yields `(Span, unquoted text, is_docstring)` per string node. Node kinds: TS/JS `comment`, `string`, `template_string`. PY `comment`, `string`. RS `line_comment`, `block_comment`, `string_literal`, `raw_string_literal`.
- `walk.rs`: `ignore::WalkBuilder` with `require_git(false)`, extension mapping and skip rules per File model, `is_test` per Test files.
- `config.rs`: `RuleSettings` with only `todo_issue_pattern` and its default. No file loading yet.
- `rules/mod.rs`: `Hit`, `Check` with only the `File` variant, `Rule` per Core types, `FAMILIES: &[&[Rule]]` listing `comments::RULES, errors::RULES, stubs::RULES, tests::RULES, debug::RULES, text::RULES, types::RULES`, and `run_rules` (rayon over files, the language filter, `Hit` to `Finding`, then sort per Output formats). Each family module except `types.rs` holds `pub const RULES: &[Rule] = &[];`.
- `rules/types.rs`: `ts/unsafe-assertion` per v0 language coverage.
- `report/human.rs`, plus `report/mod.rs` with `render_human` only.
- `main.rs`: clap `check [PATHS]...` only. Exit 0 or 1 at the default `error` gate. Any `Err` exits 2.
- `tests/rules.rs`, the fixture harness. For each dir under `tests/fixtures/rules/` whose path below that root is a rule ID (`<family>/<name>`), and each file in it whose name starts with `bad` or `good`, run `slopr check <file name>` with the fixture dir as the current dir. Parse human lines with `^(.+):(\d+):(\d+) (info|warn|error) (\S+) `. In `bad*` files, each line ending with a comment `expect: <rule-id>` must produce exactly one finding of that rule on that line, and no other finding of that rule may appear. A `bad*` file must have at least one marker. `good*` files must produce no finding of the dir's rule. The harness fails when the dir's rule ID never appears in any `bad*` result. The harness is one `#[test] fn fixtures()` that collects every failure, then panics once listing them all.
- Fixtures `tests/fixtures/rules/ts/unsafe-assertion/bad.ts`, `bad.tsx`, `good.ts`. `good.ts` holds `as const`, `as string` and `satisfies`.
- `tests/cli.rs`: `skeleton_flags_unsafe_assertion` (insta snapshot of stdout, exit 1) and `skeleton_clean_file_exits_zero`.

## Out of scope

- Loading `slopr.toml`, which is T02.
- json, sarif, `--format`, `--max-severity-exit`, which are T03.
- Suppressions, fallow, `Check::Project`, `Check::Diff`.
- Any other rule.

## Acceptance criteria

- `cargo run -- check tests/fixtures/rules/ts/unsafe-assertion/bad.ts` prints findings in the exact human format and exits 1.
- `cargo test --test rules` passes, and fails if a marker line in `bad.ts` is removed from the rule's results.
- `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` pass.
- Output is byte-identical across two runs (rayon order does not leak).
