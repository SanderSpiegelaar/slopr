## Goal

Users can turn rules off, change severities per path, exclude files, and get a starter config.

## Scope

- `config.rs`: serde model of the whole `slopr.toml` example with `deny_unknown_fields`, the `[fallow]` table included. Settings keys are validated against the rule settings table, but only for fields that exist in `RuleSettings` today (only `issue_pattern`). Add `Config::severity(rule, path) -> Option<Severity>` per Loading and precedence, with `None` meaning off.
- `main.rs`: load `./slopr.toml` if present, apply excludes and severities (drop off findings, rewrite severity), map config errors to exit 2 with `slopr: <file>: <error>` on stderr. Add `slopr init`, which writes `slopr.toml` holding the config.md example with every native rule at its default, and refuses (exit 2) if the file exists.
- `walk.rs`: apply `exclude`, and exit 2 for a PATH outside the root.
- Fixtures under `tests/fixtures/config/`, each a small dir with a `slopr.toml` and a source file.
- Tests in `tests/cli.rs`: `config_rule_off`, `config_severity_raised`, `config_override_last_wins`, `config_exclude`, `config_unknown_key_exits_2`, `config_bad_regex_exits_2`, `config_init_writes_file`, `config_init_refuses_overwrite`.

## Out of scope

- Applying `[fallow]` values, which F01 and F02 do.
- Settings keys of rules that are not built yet.

## Acceptance criteria

- All eight tests pass.
- `slopr init` output parses back with no error and equals the defaults.
